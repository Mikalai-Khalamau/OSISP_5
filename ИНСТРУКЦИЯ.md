# Лабораторная №5 (вариант 27). Инструкция: сборка, запуск, файлы, графика

Проверено на этой машине 14.11.2026: сборка MSVC (VS 2022, Release x64) без предупреждений,
`tests\run_tests.py` — **15 из 15 PASS**, эксперименты и 4 графика построены.

## 1. Что нужно установить

- Windows 10/11 x64.
- Visual Studio 2022 с компонентом **«Разработка классических приложений на C++»**
  (toolset v143, Windows 10/11 SDK).
- Python 3.8+ и пакет matplotlib: `pip install -r requirements.txt`.
  Скрипты тестов и экспериментов используют только стандартную библиотеку; matplotlib нужен
  только для графиков.

## 2. Сборка

Вариант А (проще): двойной щелчок по `scripts\build.bat` или из консоли в корне проекта:

```
scripts\build.bat
```

Вариант Б: открыть `lab05.sln` в Visual Studio 2022 → конфигурация **Release | x64** →
«Сборка → Собрать решение» (Ctrl+Shift+B).

Результат:

```
bin\x64\Release\server.exe
bin\x64\Release\client.exe
```

Промежуточные файлы: `obj\x64\Release\...`.

## 3. Запуск сервера и клиента

Все команды выполняются **из корня проекта** (там, где лежит папка `www`), иначе сервер
не найдёт файлы. Сервер и клиент — отдельные процессы; сервер запускается первым.

Терминал 1 — сервер:

```
bin\x64\Release\server.exe --host 127.0.0.1 --port 20113 --www www
```

Терминал 2 — клиент (каждый запрос открывает новое TCP-соединение):

```
bin\x64\Release\client.exe --port 20113 --path /1kb.txt --print-body
bin\x64\Release\client.exe --port 20113 --method HEAD --path /64kb.txt
bin\x64\Release\client.exe --port 20113 --path /64kb.html --count 100 --id 2
bin\x64\Release\client.exe --port 20113 --raw "GET /../secret.txt HTTP/1.1\r\nHost: x\r\n\r\n"
```

Остановка сервера: **Ctrl+C**, **Ctrl+Break** или ввести `q` + Enter. Сервер корректно
закрывает сокеты, выводит статистику `STATS` и завершается с кодом 0.

Справка по всем параметрам: `server.exe --help`, `client.exe --help`.
Коды возврата клиента: 0 — успех; 1 — сетевые ошибки; 2 — неверные параметры;
3 — не удалось разрешить адрес; 4 — статус ответа не равен `--expect`.

Порт по варианту: `20000 + STUDENT_ID = 20113`. Адрес по умолчанию — только `127.0.0.1`.

## 4. Автоматические тесты (15 сценариев)

```
python tests\run_tests.py --bin bin\x64\Release
```

Скрипт сам запускает `server.exe`, проверяет GET/HEAD, коды 200/400/404/405,
Content-Length/Content-Type, частичный приём, тайм-ауты, обрывы, лимит заголовков,
обход каталога, 5 одновременных клиентов, занятый порт и штатное завершение,
затем останавливает сервер. Ожидаемый результат: `Итого: 15 тестов, прошло 15, провалено 0`.

## 5. Эксперименты и графики

```
python scripts\run_experiments.py --bin bin\x64\Release
python scripts\plot_results.py
```

`run_experiments.py` выполняет 4 конфигурации по заданию (1 и 3 клиента × 1 КБ и 64 КБ),
по 200 запросов на клиента, по 3 запуска каждой конфигурации, и пишет CSV в `data\`.
`plot_results.py` строит 4 PNG в `data\plots\`.

Дополнительный эксперимент «от преподавателя» (пишется отдельно, в `custom_*.csv`):

```
python scripts\run_experiments.py --bin bin\x64\Release --only-custom --custom-clients 5 --custom-path /64kb.html --custom-count 100
```

Пересоздать тестовые файлы (детерминированно, SEED = 11961): `python scripts\gen_www.py`.

## 7. Графический материал: что где и как смотреть

### 7.1. Графики экспериментов

- `data\plots\plot1_total_time_vs_clients.png` — среднее время запроса от числа клиентов.
- `data\plots\plot2_throughput_vs_clients.png` — пропускная способность от числа клиентов.
- `data\plots\plot3_total_ms_boxplot.png` — распределение времени отдельных запросов (boxplot).
- `data\plots\plot4_time_breakdown.png` — из чего складывается время запроса (connect / ttfb / остальное).

Открыть можно любым просмотрщиком изображений (двойной щелчок в Проводнике).
Пересобрать после новых измерений: `python scripts\plot_results.py`
(или `python scripts\plot_results.py --show`, чтобы сразу показать окна).

Исходные данные для отчёта: `data\raw_results.csv` (все запросы) и `data\summary.csv`
(сводка по запускам), таблицы `data\table2.csv`, `data\table3.csv`,
параметры запуска — `data\experiment_meta.json`.

### 7.2. Диаграмма последовательности

- Исходник PlantUML: `diagrams\sequence.puml` (редактируемый текст).
- Уже отрендерено: `diagrams\sequence.png` и `diagrams\sequence.svg` — можно открыть
  просмотрщиком или вставить в отчёт.
- Дубликат в Mermaid: `diagrams\sequence.mermaid`.

Как перерендерить PlantUML:

1. VS Code + расширение **PlantUML** (`jebbs.plantuml`), открыть `sequence.puml`,
   нажать Alt+D (предпросмотр) или Ctrl+Shift+P → «PlantUML: Export Current Diagram».
2. Либо скачать `plantuml.jar` (plantuml.com/download), нужна Java:
   `java -jar plantuml.jar -tpng diagrams\sequence.puml`.
3. Либо вставить текст из `sequence.puml` на plantuml.com.

Mermaid: открыть `sequence.mermaid` в VS Code и включить предпросмотр Markdown
(или вставить содержимое на mermaid.live).

### 7.3. Архитектурная схема

- Исходник draw.io: `diagrams\architecture.drawio` (XML, редактируется).
- Открыть: [app.diagrams.net](https://app.diagrams.net) → File → Open From → Device,
  выбрать `architecture.drawio`; либо установить draw.io Desktop и открыть файл.
- Экспорт в PNG/PDF: в draw.io File → Export as → PNG/PDF.
- Готового PNG этой схемы в проекте нет — при необходимости экспортируйте из draw.io.

## 8. Полезно знать

- Если порт занят, сервер печатает `bind ... 10048` и завершается с ненулевым кодом.
  Занятый порт можно проверить: `netstat -ano | findstr 20113`.
- Для экспериментов и тестов порт по умолчанию 20113; другой порт задаётся `--port`.
- `wall_ms` в таблице 2 включает запуск процессов клиентов, поэтому он больше суммы
  времён отдельных запросов; сравнение конфигураций корректно, но абсолютные значения
  зависят от машины.
- `data\plots_sample\` и `data\sample_data_for_plot_check.csv` — **демонстрационные**
  данные для проверки скрипта построения графиков, не результаты эксперимента.
- В проекте пока нет каталога `report\`, файла `.gitignore` и Git-репозитория.
  По требованиям методички их нужно создать и вести историю разработки.
- Файлы `bin\`, `obj\`, `.vs\`, `data\runs\` — результаты сборки/запусков, их не нужно
  включать в отчёт (и стоит добавить в `.gitignore`).
